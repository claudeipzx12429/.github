<p>长期项目用的静态住宅出口，最怕的不是买贵，而是买回来发现几个关键参数当初没问：到期后地址保留几天、并发上限到底指端口还是连接、能不能指定城市。这些内容在合同里通常是小字，在使用中却决定成败。下面按一份参数说明书的结构逐项列出该确认什么，每项配一个验收动作，照着填完再签字。</p>

<h2>一、出口标识：地址、ASN、地区三项要对得上</h2>
<p>出口标识是这张说明书的第一栏，也是后面所有判断的基准。地址要记全，包括网关和可用端口；ASN 决定这条地址的出身；地区要细到城市，不能只写国家。三项之中任一项与实际不符，都会在账号侧留下矛盾的痕迹。</p>
<h3>这三项怎么核对</h3>
<p>地址用 ipinfo 或 whois 查归属与 ASN，地区看查询结果里的城市字段而非仅国家字段，路由用 traceroute 看最后一跳落在运营商还是机房。核对完把结果截图存档，替换时用来对比，避免换到一条「同国家不同城市」的线路还以为一致。</p>

<h2>二、容量参数：带宽、并发、端口各说各的</h2>
<p>这三个词经常被混用。带宽是速率上限，单位 Mbps；并发是同时保持的连接数上限；端口是接入入口的数量。同一个套餐里三者独立约定，任何一个到顶都会表现为「卡」，但解法完全不同。签之前要把三个数字分别写下来。</p>
<p>特别要问清楚并发的计量口径：是 TCP 连接数、是活跃会话数、还是同时在线的账号数。三者可能差好几倍。一个账号开一个浏览器标签可能是三到六条连接，按连接数计的 100 并发和按账号数计的 100 并发，实际能承载的量级完全不同。</p>

<h2>三、租期参数：起租、续费、保留</h2>
<p>长期项目最怕的是续费环节出意外：忘记续费导致地址被回收，重新分配的地址换了段，等于环境重建。这一栏要写清起租日期、续费窗口、自动续费是否默认开启、以及欠费后地址保留多久。</p>
<h3>续费窗口和自动续费的两个坑</h3>
<p>第一个坑是自动续费默认关闭，需要手动操作，而提醒邮件发到了没人看的邮箱；第二个坑是自动续费默认开启，但绑定的支付方式过期，扣款失败后进入欠费状态。两种都要在日历里加提前七天的提醒，不依赖服务商通知。</p>

<h2>四、可靠性参数：可用性怎么算、替换怎么触发</h2>
<p>「可用性 99.9%」这句话要问分母：是按自然月分钟数算，还是按工作时段算；是单条线路统计，还是整个资源池统计。分母不同，实际含义可能差一个量级。同理，替换的触发条件要写成可判定的句子，比如连续不可用超过 30 分钟。</p>
<h3>可用性的分母是什么</h3>
<p>按月统计的 99.9% 意味着每月允许约 43 分钟不可用；如果只统计工作时段，允许的绝对时长会更短但覆盖不到夜间。对夜间也在跑的业务，必须要求按 7×24 统计，并明确以哪一方的监测数据为准。</p>

<h2>五、环境侧要固定的几个值</h2>
<p>出口是外部参数，环境是内部参数，两者必须一起固定。出口在美国西部，环境却是东八区时区加中文首选语言，这种组合本身就是矛盾信号。这一栏要写清时区、浏览器语言、系统区域、以及常用分辨率。</p>
<h3>时区、语言、UA 的具体取法</h3>
<p>时区取自出口所在城市的 IANA 名称，例如 America/Los_Angeles；浏览器语言设为 en-US 并把中文从首选列表里去掉；UA 用真实浏览器的默认值，不要自行拼接。三项改完在页面里执行一次检测，确认返回值和设定一致再开始登录。</p>

<h2>常见问答</h2>
<h3>静态地址真的永久不变吗？</h3>
<p>答：在租期内通常不变，但服务商侧线路调整、上游回收等情况仍可能导致变更。合同里应写明变更的提前通知义务，自己也要做地址监控。</p>
<h3>并发按连接数计，怎么换算成账号数？</h3>
<p>答：先实测单账号的稳定连接数，用浏览器开发者工具看同时保持的请求数，取一个偏保守的值，再用总并发除以它。不同操作习惯差别很大，实测比估算可靠。</p>
<h3>可以要求指定具体城市吗？</h3>
<p>答：多数服务商支持指定城市或至少指定州，但要额外确认是否有库存。下单前问清楚，避免付了款才被告知只能给同国其他城市。</p>
<h3>续费涨价常见吗？</h3>
<p>答：首年优惠、续费恢复原价是常见做法，长期项目应按续费价做预算，而不是按首年价。签长约时把续费价格写进附件更稳妥。</p>

<h2>合规提示</h2>
<p>本文的参数清单为通用整理，仅供参考，具体条款以服务商合同为准。</p>
<p>使用静态住宅出口应限于自有账号的正当业务，不得用于规避平台规则、虚假注册或其他违规用途。</p>
